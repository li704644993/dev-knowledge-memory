# Repository Guidance

This repository distributes a local development-knowledge workflow, not business knowledge or an autonomous agent service.

- Machine-specific paths belong in the root configuration, not in the distributed skill.
- Preserve unrelated Codex settings and instructions. The installer owns only its marked blocks and installed skill files.
- Keep Obsidian knowledge scoped to the configured development directory. Repository source, configuration, and relevant repository documentation remain available.
- Do not include personal notes, company source, credentials, conversation exports, or real deployment identifiers in distributable files. Examples use fictional systems.
- Capture is performed by the active coding agent at its completion checkpoint. Do not add background agents, scheduler jobs, interception hooks, or another retrieval service.
- Do not write tests or compute checksums unless explicitly requested. Validate syntax, configuration rendering, and installer behavior using an isolated local configuration.
- Do not infer implementation rules from retrieved table names. A knowledge note is evidence to check, not authority to override the current user or repository.
